# Evaluation and safety

## Main risks

| Risk | Visible symptom | Control |
|---|---|---|
| Hallucinated competence | Polished explanation without mechanism or transfer | Require teach-back, boundary case, and new problem |
| False confidence | Familiarity or one correct answer treated as mastery | Use delayed retrieval and mixed questions |
| Answer dumping | Model completes all reasoning for the learner | Fade help and expose only the next useful hint |
| Blanket repetition | Low confidence triggers full-content replay | Require a diagnostic error before rewatching |
| Outcome overclaim | Artifact quality presented as proof of score improvement | Separate design evidence from learner-outcome evidence |
| Hidden assumptions | Formula or plan ignores conditions | State units, assumptions, failure cases, and scope date |
| Harmful labeling | Feedback turns an error into a judgment of ability | Diagnose the task step, not the learner’s identity |
| Stale exam guidance | Prior scope is treated as current | Mark the evidence date and recheck authoritative sources |

## Acceptance test for an explanation

An explanation passes only if:

- a learner can identify the motivating problem;
- the mechanism can be reconstructed without the source;
- notation is tied to plain language and units;
- assumptions and edge cases are named;
- at least one new problem can be solved;
- a wrong answer can be mapped to a targeted repair.

## Outcome claim policy

Use:

- “designed to support retrieval”;
- “contains 19 diagrams”;
- “includes an evidence-gated progression rule.”

Do not use without a study:

- “proven to improve retention”;
- “guarantees AIR under 100”;
- “works for every learner”;
- “eliminates hallucinations.”
